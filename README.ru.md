# MikroTik Address List Tool

[English](README.md) | Русский

Утилита командной строки для управления списками адресов IPv4 в MikroTik RouterOS через нативный API. Поддерживает добавление и удаление DNS-имён, IPv4-адресов, подсетей и диапазонов, просмотр списка и поиск потенциально устаревших DNS-записей.

## Требования

- Python 3.10 или новее (используйте поддерживаемую версию с актуальными исправлениями).
- `librouteros==4.2.2`, устанавливается из `requirements.txt`.
- RouterOS 6.43 или новее — целевой минимальный уровень для используемой аутентификации. Перед эксплуатацией проверьте совместимость с конкретной версией RouterOS.
- Отдельная учётная запись RouterOS с минимальными необходимыми правами API, чтения и записи. Для просмотра и предварительных проверок по возможности используйте учётную запись только для чтения.
- Доступный сервис `api-ssl` с доверенным сертификатом (по умолчанию TCP 8729). Ограничьте доступ сетью управления и разрешёнными адресами источников.

## Установка

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python add_blocked.py --help
```

Команды предназначены для POSIX-оболочки. В Windows активируйте виртуальное окружение соответствующим платформе скриптом.

## Конфигурация

```bash
install -m 600 add_blocked.conf.example add_blocked.conf
```

Отредактируйте `add_blocked.conf` в текущем рабочем каталоге либо укажите другой путь через `--config`:

```ini
[credentials]
host = router.example.org
user = address-list-service
password =
```

Передайте настоящий пароль через защищённый конфигурационный файл или переменную `ADD_BLOCKED_PASSWORD`, устанавливаемую менеджером секретов либо планировщиком. Переменные `ADD_BLOCKED_HOST`, `ADD_BLOCKED_USER` и `ADD_BLOCKED_PASSWORD` имеют приоритет над соответствующими параметрами INI, в том числе если содержат пустое значение. Все три параметра должны быть непустыми. Учётные данные должны содержать только ASCII-символы; адрес хоста указывается без порта и схемы URL. Интерполяция паролей отключена. В POSIX файл с паролем не должен предоставлять права группе и остальным пользователям (используйте `chmod 600`). Не добавляйте секреты в Git и не выводите окружение в CI. В Windows ограничьте доступ к файлу через ACL.

По умолчанию используется TLS с проверкой сертификата. Для собственного удостоверяющего центра укажите доверенный сертификат:

```bash
python add_blocked.py --api-ca-file /path/to/ca.pem --list
```

Сертификат должен соответствовать имени хоста; при подключении по IP сертификат должен содержать соответствующий IP SAN. Для существующих конфигураций с обычным API явно укажите `--api-plain` (TCP 8728). Этот режим передаёт учётные данные без шифрования и допустим только в доверенной изолированной сети управления. `--insecure` относится только к загрузке HTTPS-источников и не отключает проверку TLS RouterOS.

## Использование

```bash
python add_blocked.py example.org example.net 192.0.2.10
python add_blocked.py -A blocked -f domains.txt --dry-run
python add_blocked.py -f https://example.org/domains.txt --resolve-timeout 5
python add_blocked.py --list
python add_blocked.py --delete example.org --dry-run
python add_blocked.py --delete example.org
python add_blocked.py --clean --dry-run
python add_blocked.py --clean --confirm-clean --max-delete 20
```

URL в примерах условные. Используйте только доверенные источники. Входной файл содержит по одной записи на строку:

```text
# Example entries
example.org
example.net
192.0.2.10
198.51.100.0/24
203.0.113.10-203.0.113.20
```

Пустые строки и строки-комментарии с `#` игнорируются. Локальные файлы читаются как UTF-8 (BOM допустим); для HTTP(S) применяется объявленная кодировка либо UTF-8. Некорректный ввод прерывает работу до изменения роутера. Имена приводятся к нижнему регистру, завершающая DNS-точка удаляется, интернационализированные имена преобразуются встроенным IDNA-кодеком Python, IPv4-подсети нормализуются до адреса сети (`/32` преобразуется в одиночный IP). Дубликаты исключаются с сохранением порядка. IPv6, URL в качестве записей, wildcard-домены и формат hosts не поддерживаются. Скрипт не создаёт правила firewall: для фильтрации требуется существующее правило, использующее список.

Без записей или файла режим добавления/удаления запрашивает одну строку адресов через пробел, в том числе при перенаправлении стандартного ввода. Введите `example.org example.net` для добавления или `-d example.org example.net` для удаления. Пустая строка завершает работу успешно; конец потока без ввода — с кодом 1. Например:

```bash
python add_blocked.py
```

Пустой файл приводит к успешному завершению без подключения. `--list`, `--delete` и `--clean` взаимоисключающие; просмотр и очистка не принимают входные записи.

## Параметры

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `sites` | — | Позиционные аргументы с адресами |
| `-f, --file` | — | Локальный файл или URL |
| `-A, --addr-list` | `blocked` | Целевой список, имя в ASCII |
| `-l, --list` | выкл. | Вывод адресов в stdout |
| `-d, --delete` | выкл. | Удаление совпадающих статических записей |
| `-c, --clean` | выкл. | Поиск потенциально устаревших статических DNS-записей |
| `-C, --dry-run` | выкл. | Предпросмотр без изменения роутера |
| `--confirm-clean` | выкл. | Явное разрешение очистки |
| `--max-delete` | `100` | Максимум записей за один запуск удаления/очистки (1–100000) |
| `--bulk-size` | `50` | Размер пакета удаления (1–1000) |
| `--resolve-timeout` | `0` | Локальный DNS-таймаут на имя в секундах; 0 отключает проверку |
| `--resolve-workers` | `32` | Число DNS-потоков (1–128) |
| `--source-timeout` | `10` | Сокетный таймаут источника, секунды |
| `--allow-http` | выкл. | Явное разрешение HTTP-источников |
| `--insecure` | выкл. | Отключение проверки сертификата HTTPS-источника; не рекомендуется |
| `--config` | `add_blocked.conf` | Путь к INI-файлу |
| `--api-timeout` | `10` | Сокетный таймаут RouterOS, секунды |
| `--api-port` | `8729` / `8728` | Переопределение порта TLS / обычного API |
| `--api-plain` | выкл. | Явное разрешение незашифрованного API |
| `--api-ca-file` | системные CA | CA-файл для TLS RouterOS |
| `--debug` | выкл. | Подробное диагностическое логирование |
| `-h, --help` | — | Справка |

## Безопасность очистки

Очистка сохраняет исходную эвристику: корректное статическое DNS-имя считается кандидатом, если в том же списке нет динамической IPv4-записи с соответствующим комментарием. Статические IP, подсети, диапазоны, отключённые и динамические записи, а также нераспознанные адреса защищены. Явное удаление допускает удаление отключённых статических записей, но пропускает динамические и возвращает ненулевой статус при их наличии среди совпадений. Перед очисткой план считывается повторно; при изменении идентификаторов или адресов кандидатов операция прерывается.

**Отсутствие динамической записи не доказывает несуществование домена.** Ошибки DNS роутера, временные сбои и асинхронное обновление могут привести к ложным срабатываниям. Всегда проверяйте `--clean --dry-run`, работоспособность DNS роутера, создавайте резервную копию конфигурации и задавайте подходящий `--max-delete` перед явным разрешением очистки. Лимит считается по строкам, а не уникальным именам; предпросмотр не обрезается. План всё ещё может измениться между последним чтением и записью; API не предоставляет транзакцию или откат для этих операций.

## Production-эксплуатация

- Используйте TLS с проверкой сертификатов для RouterOS и загрузки источников. HTTP и небезопасный HTTPS — явно включаемые режимы совместимости; перенаправление HTTPS на HTTP запрещено. Ограничьте исходящие сетевые соединения и используйте доверенные источники; URL задаются оператором, а не недоверенными пользователями многопользовательской системы.
- Размер источника ограничен 16 МиБ и 100000 входных записей; обработка целевого списка ограничена 100000 строк. Библиотека может буферизовать ответ роутера до проверки лимита приложением. Поддерживайте разумный размер списков и источников.
- DNS-проверка выполняется на клиенте, а не на роутере, и только при её включении. Каждый запрос выполняется в отдельном процессе с собственным таймаутом. Запуск процесса и особенности системного DNS/сети могут добавить задержку. Таймауты API и источника относятся к сокетным операциям, а не ко всему заданию.
- Исключайте одновременную работу с одним роутером/списком, в том числе других клиентов записи. Идемпотентность действует относительно снимка списка; конкурентные изменения и перезагрузки роутера могут его инвалидировать. Используйте внешнюю блокировку и общий таймаут задания, например в Linux с приватным доступным для записи каталогом блокировок:

```bash
flock -n /path/to/private/add_blocked.lock timeout 10m \
  /path/to/.venv/bin/python /path/to/add_blocked.py \
  --config /path/to/add_blocked.conf --file /path/to/domains.txt
```

- При первой ошибке API операции записи прекращаются. Ошибка или прерывание могут оставить предыдущие изменения применёнными, в том числе часть пакета удаления. Автоматический повтор и откат не выполняются. Повторно прочитайте список и сверяйте состояние перед перезапуском.
- Просмотр списка и план dry-run выводятся в stdout; диагностические сообщения с отметками времени и итоговые счётчики — в stderr. Сырые исключения API, пароли и URL источников не печатаются. Имена адресов и идентификаторы могут присутствовать в журналах; ограничивайте доступ к ним и срок хранения.
- Регулярно проверяйте обновления зависимостей и сообщения об уязвимостях; фиксация версии не гарантирует отсутствие уязвимостей.

## Коды завершения

| Код | Значение |
| --- | --- |
| `0` | Успешная операция или пустой файл |
| `1` | Ошибка выполнения, пропуск DNS-записи или совпадающей динамической записи, превышение лимита удаления |
| `2` | Некорректные параметры CLI |
| `130` | Прерывание с клавиатуры |

Внешние обёртки `timeout` и `flock` могут возвращать дополнительные коды. Пропуск по DNS не препятствует добавлению других корректных кандидатов, но итоговый статус будет ненулевым.

## Тестирование

```bash
python -m unittest discover -s tests -v
python -m py_compile add_blocked.py tests/test_add_blocked.py
```

Тесты используют mock API и проверку локального резолвера для `localhost`; реальный роутер и удалённые источники не требуются. Они не подтверждают реальную совместимость с RouterOS. Перед применением к рабочему списку проверьте TLS, права чтения и записи, добавление, пакетное удаление и очистку на отдельном тестовом списке в используемой версии RouterOS.
